# Automatic approval policy

Changes of any size, including large changes and public API changes, are eligible
for automatic approval when sufficient code review has happened on the PR.

Require completed reviews from both CodeRabbit and Copilot covering the current
changes. Verify reviewer identity, the commits reviewed, and coverage of changes
made since earlier reviews. A review request, quota-exhaustion message, skipped
review, or failed run does not count as a completed review. If either provider's
coverage is missing, stale, partial, or inconclusive, withhold approval.

Assess the substance and thoroughness of both reviews in proportion to the scope
and complexity of the change. Their presence alone is not sufficient: verify that
every finding has been fixed in the current code or addressed with an evidence-backed
explanation. Explain why the combined review coverage is sufficient, then perform
your own independent review.

All discussions must be substantively addressed, including general PR comments
and resolved or outdated findings. Apply the relevant `AGENTS.md` instructions,
especially storage-format compatibility and sensitive information handling.

Require human approval for CI/workflow/release configuration changes. Withhold
approval for any unresolved correctness or security concern.

For dependency updates, inspect upstream release notes and source changes between
the old and new version. Verify the version and pinned commit or integrity hash.
Do not approve source/registry changes, new install/build hooks, unexpected
transitive dependencies, ownership changes, or updates whose provenance cannot
be established. Failure to obtain upstream evidence means human review.

Review requirements belong here in prose; the workflow and review skill do not
hardcode reviewer identities or change-size limits.
